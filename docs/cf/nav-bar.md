# The nav bar spans its parent, yields nothing, and reserves the boxes that change at runtime

`.strand-nav__inner` has no max-width and no auto margins: a bar is chrome that spans its parent and insets by its own padding (32px, 16px below 480 where a desktop gutter would push the account control out of the bar); a bar that wants a reading measure is placed inside a Container by the consumer. Its `min-height: inherit` picks up `--strand-nav-height` so the mobile bar does not read as a squished logo, and the glass variant pins its height to that token so `body:has(.strand-nav--glass) { padding-top }` (with a `body.strand-glass-nav-active` twin the vanilla runtime toggles for browsers without `:has()`) stays honest. Exactly one auto margin, on `__actions`: two in one row make the first absorb all the free space. `__items` and `__actions` are `flex: none`, and `__actions` also carries `min-inline-size: max-content`, because a percentage-sized child contributes nothing to a parent's intrinsic size and the box measured smaller than the things inside it. Destinations never wrap: a bar fits them or hands them to the mobile menu. `__slot--reserve` pins the slot's inline size (`--strand-nav-slot-reserve`, tighter below the mobile breakpoint) so an auth affordance swapping identity cannot move its siblings. `__slot` and `__actions` stay visible on mobile; which actions survive is the consumer's knowledge. The wordmark's hover and pressed states change colour only (pressed darker than rest) so its metrics never reflow the bar. `right: var(--strand-scrollbar-gap, 0px)` keeps a fixed bar aligned with content Dialog's scroll lock has padded. The instrument variant composes `.strand-nav.strand-nav--instrument` so it outweighs the base rules whatever the bundle order.
