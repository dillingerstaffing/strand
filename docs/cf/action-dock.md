# The action dock is fixed to the viewport, hidden by default, and never covers a toast

`.strand-actiondock` is `position: fixed`, never sticky: sticky is relative to a scroll container and leaves the thumb zone exactly when the reader reaches the bottom of a list, and the contract is that the dock's position is a function of the viewport alone. Its bottom offset carries `env(safe-area-inset-bottom)` because a notched phone's home indicator overlaps the viewport bottom, and headless browsers resolve the inset to 0, so a consumer testing locally never sees the control they shipped underneath it. Its z-index sits above content and below the nav's mobile menu (100) and the toast (1100), because a dock that covered a toast would hide the confirmation of the action it just triggered. Hidden means translated fully out of the viewport with `visibility` riding the transition, so the hidden dock leaves the accessibility tree and takes no pointer events; an absent `data-strand-actiondock` attribute means hidden, so a server-rendered consumer that never flips it occludes nothing. That attribute is the whole runtime. One dock per view: two docked actions are a toolbar, which is a different pattern.
