# A control's painted state is read from where the platform keeps it, never mirrored into a class

`Checkbox` and `Radio` paint checked, mixed and disabled from the native input (`:checked`, `:indeterminate`, `:disabled`, `:enabled`) through the sibling combinator, and `Switch` paints on from `aria-checked="true"` on its track, so an uncontrolled control (`defaultChecked`, or a plain `<input>` in class-only markup) renders right with no script computing a `--checked` class, and the announced state and the painted state cannot drift because they are one attribute. `role="checkbox"` and `aria-checked` never appear on a native checkbox: the element and its `indeterminate` property already expose them. The wrapper `<label>` has no state of its own, so its disabled dimming reads the input through `:has(...:disabled)`; a browser without `:has()` (Firefox before 121, Chrome before 105, Safari before 15.4) still gets a disabled control, only undimmed, and there is no class fallback because a class carried by hand is the drift this rule removes. Both check glyphs are always in the markup and the sheet shows one (`__icon--check` on `:checked:not(:indeterminate)`, `__icon--mixed` on `:indeterminate`), so class-only consumers emit the same markup for every state.

Where: `Checkbox.css`, `Radio.css`, `Switch.css` and their components under `packages/strand-ui/src/components/`; the Vue and Svelte ports mirror the markup.
