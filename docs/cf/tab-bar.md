# The tab bar is fixed, opaque, styled from `aria-current`, and reserved for only as long as it shows

`.strand-tabbar` is fixed (not sticky, for the action dock's reason) with `env(safe-area-inset-bottom)` under a fallback, and it is opaque: behind a translucent bar the labels' contrast is a function of whatever scrolls beneath, and a ratio that changes as the reader scrolls is not a ratio. Its background fallback names a token that exists (`--strand-surface-elevated`); a fallback to an undefined variable resolves to transparent, which looked plausible in review. Height, item size, label size and distribution are custom properties with the design's values as fallbacks; the label size token does not add a rung to the type scale. `__item` is `min` height (a wrapping label grows the bar rather than spilling out of it), and labels wrap rather than truncate: a destination the reader cannot read is not a destination, and a bar with too many is what 19.1.1's count test refuses. The current destination is `[aria-current="page"]`, both the accessible answer and the styling hook, in blue-deep (text tier). The focus ring is inset because an outward ring on an item flush against the viewport's bottom edge is clipped by the edge. `.strand-tabbar-offset` reserves the bar's height on the scrolling content only below 767.98px, the complement of `strand-hide-from-md`, and shares `--strand-tabbar-height` so a taller bar cannot outgrow its reservation; a consumer hiding the bar elsewhere sets the token to 0px at its own breakpoint. It is not `.strand-tabs` (panels inside one view) and not the action dock (one action); the two may coexist by state, never stacked.
