# A surface recolours the primitives inside it through their tokens, never by selector

Every colour a primitive changes on a surface is a custom property the primitive reads with its light value as the fallback (`color: var(--strand-overline-color, var(--strand-gray-500))`), and a surface is a flat list of those properties on the surface class (`.strand-instrument-viewport, .strand-body--instrument { --strand-overline-color: var(--strand-gray-400); ... }`). Nothing may write `.strand-instrument-viewport .strand-overline { color }` again: that shape depends on file order and specificity to win, which is why the light detail panel used to inherit dark alert colours and editorial values sat unreadable on the abyss. A light island (`.strand-detail-panel`, `.strand-surface-light`) resets every token a dark surface sets to `initial`, so the primitive falls back to its own light value; it lists an explicit value only where the island deliberately differs. The token names follow the class: block, element, modifier, then a pseudo-class state (`hover`, `pressed`, `focus`), then the property (`color`, `bg`, `border-color`, `underline`). Consumers may set the same properties on any container to theme a region.

Where: every `components/<Name>/<Name>.css` that reads a `--strand-<block>-*` token; the surface blocks at the end of `InstrumentViewport.css`, `FeatureSurface.css`, `Section.css`, `DetailPanel.css` and `utilities.css`; `scripts/contrast-check.mjs`.
